# Design

MDBird takes its layout cues from the Gmail workspace and uses tonal surfaces, rounded cards, and state layers from Material Design 3 Expressive. Different corner radii distinguish panes, input fields, and selected navigation items. The Compose button transitions from a rounded rectangle to a pill shape. Spaces and calendar view buttons change shape to indicate selection. Animations respect the system's reduced motion preference. [Material Design 3](https://m3.material.io/)

## Stylesheet entry points

| File | Purpose |
| --- | --- |
| `userChrome.css` | Loads shared styles and window components, then applies local window overrides |
| `userContent.css` | Loads shared styles and message content styles |
| `theme/interface.css` | Maps design tokens to Thunderbird and Gecko variables for built-in controls and loads menu and built-in page styles |
| `theme/tokens.css` | Loads the palette and defines shared surfaces, corner radii, type sizes, and state colors |
| `theme/components/` | Styles the top toolbar, navigation, message list, message pane, compose window, spaces, and menus |
| `theme/pages/` | Styles Settings, Account Settings, Address Book, search, import, and management pages |
| `theme/message-content.css` | Sets margins and quote styles for plain-text messages and styles the compose editor surface |
| `search-addon/` | Registers the sidebar search button, popup, and global search entry points in the main window |

Thunderbird uses separate documents for the main window, three-pane layout, message pane, and built-in tabs. The main window and mail panes use the user interface stylesheet. Built-in tabs such as Settings, Account Settings, and Address Book use the user content stylesheet. Both entry points load the same `interface.css`, which scopes its interface rules by URL to Thunderbird's built-in documents. The message styles identify plain-text bodies by the message protocol and the wrapper generated by Thunderbird. The compose editor uses the dedicated URL `about:blank?compose`. [Thunderbird custom stylesheets](https://support.mozilla.org/en-US/kb/userchromecss-js-usercontent-unsupported)

## Controls and layout

The theme uses Thunderbird's existing control variables wherever possible. Windows, cards, and popups use the canvas, content surface, and tonal surface, respectively. Focus outlines use the primary color. In forced colors mode, the theme uses system colors. Folders, Settings, and Address Book use the same tonal selection colors. Calendar events and message tags use their colors from Thunderbird's settings.

Thunderbird calculates message row heights from the font and interface density. The theme adjusts corner radii, text hierarchy, and state colors within those row boxes. Native splitters manage the three-pane layout. The spacing token sets both the gaps around cards and the space occupied by the splitters.

The theme hides the global search box in the top toolbar by default. Quick Filter is available in the message list. At window widths of 900 CSS pixels or more, the tab bar fills the space beside the unified toolbar and window controls. The menu bar occupies its own row when visible. Narrow windows and the toolbar customization screen use Thunderbird's native layout.

XUL menus use the surface variables on `menupopup` and `panel`. HTML popups use the variables on `panel-list` and `panel-item`. Thunderbird handles menu scrolling, keyboard navigation, and check marks. The operating system or Thunderbird draws system title bars, system menus, and controls that expose no styling hooks.

## Global mail search

MDBird Search uses Thunderbird's MailExtension Experiment API to add a button and a popup to the main window's Spaces Toolbar and handle the existing global search menu item and shortcut. The popup uses the theme's colors and corner radii. When you submit a keyword, the add-on passes it to Thunderbird's global index. Results appear in the list or faceted view selected in Thunderbird's settings. Disabling the add-on removes the popup, button, and event listeners. [Thunderbird Experiment API](https://developer.thunderbird.net/add-ons/mailextensions/experiments)

## CSS cascade

Thunderbird's built-in stylesheets use the CSS author origin. MDBird uses user stylesheets and marks declarations as `!important` where it needs to override Thunderbird's values. MDBird's shape and spacing tokens use normal priority so you can adjust them with local overrides. When extending a palette, use `light-dark()` to set light and dark values for the same role. Controls use the value that matches Thunderbird's color scheme.
